Role Assistant Foundry: architecture

Role-based AI assistants for small companies, built on Meta Muse models. Rules decide structure (org chart validity, skill lists, approval limits); the model only writes words and picks tool arguments.

solid border: builtdashed border: not builtdashed arrow: conditional link or link to a part not built

1. Request path

Any model failure returns demo_mode: true with a label; private mode never falls back to the Meta API. Source: app.py, store.py, muse.py, chart.py, vision.py, voice.py, sam.py, scripts/private_modal.py, scripts/deploy.ps1, Dockerfile.

2. Order workflow

An invite approves only its own role's step (409 wrong_role, reason other_role), and one named person cannot approve two steps of an order (409 wrong_role, reason same_person). Orders and tool results stay in the browser. Source: workflow.py, app.py, rules.py, tools.py, store.py, static/join.js.

3. Hierarchy

  1. Groupmargin floor, approval limit, banned skills
  2. Subsidiarymay only tighten the rules above
  3. Company ruleschecked against levels above
  4. Departmentnot built
  5. Teamnot built

A unit below may keep or raise the margin floor, keep or lower the approval limit, and must keep every parent ban (it may add more); a looser value is refused. The strictest value on any level wins. Source: rules.py (LEVEL_RULES, validate_child_rules, bind_levels), app.py (/api/levels, /api/handoff-schema).

4. Data: stored vs never stored

Stored (8 tables deleted with the sandbox after 24 h; daily_cost is kept)

  • sandboxes, companies, assistants
  • peopleinvite token, display name, role; no email, activity or metrics
  • personal_rulesreadable only with that person's invite
  • packageshanded-off business documents
  • decisionsaccept or return
  • approvalshash of the invite name per step, only to stop one person approving twice; no performance or habit metrics
  • daily_costservice-wide USD per day, no who or what; not deleted with a sandbox

Never stored

  • Chat messages and history
  • Workflow orders and tool results
  • Suggested fixes (until resent)
  • Photos (sent once, dropped)
  • Voice recordings
  • Pasted customer messages
  • Morning brief, onboarding ticks
  • Handover draft until sent
  • Habits, speed, experience, per-person statistics
  • Training: paid Standard use is excluded and -contributor ids are refused; the free-credit demo may be used by Meta (Meta's billing page says content may be used for product improvement while free credits are in use)

Source: trust.py (STORED, NEVER_STORED), store.py.
